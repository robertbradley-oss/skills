# Audit agent skills

Use the installed `skill-creator` for current packaging and validation rules. This skill adds an instruction-quality review, not another authoring framework.

- Check the discovery description: one clear capability and trigger; avoid exhaustive synonyms and unrelated catchalls.
- Check what changes the agent's decisions. Retain local knowledge, useful preferences, fragile-operation contracts, and user-invoked workflows; remove generic tutorials and repeated policy.
- Keep the entrypoint small. Load detailed modes, examples, and scripts only when the current task needs them. A short standalone skill needs no router.
- Distinguish audit, planning, and implementation. A combined fix-and-verify request should reach verified completion without an invented review pause.
- Ask only about consequential missing decisions. Existing user authorization remains valid; preserve real external-action and data boundaries.
- Check live tool contracts, linked resources, canonical source copies, and conflicts with project instructions or adjacent skills.
- Validate metadata with the installed creator validator. For meaningful behavioral changes, use representative requests to check routing, scope, completion, and failure handling. Metadata validation alone does not prove runtime behavior.

Report concrete findings with paths, impact, and a recommended correction. For authorized edits, fix the identified problems and revalidate. Do not change invocation policy or delete capabilities merely to reduce the skill count.
