# Reference comparison

Choose a few analogous current surfaces, not an arbitrary number of screenshots. Record useful evidence internally; a separate report is optional.

| Dimension | Evidence to inspect | Failure to avoid |
| --- | --- | --- |
| Composition | Page shell, navigation, task grouping, reading order | Copying a marketing layout into an operational screen |
| Density | Comparable lists, forms, or editors at normal use | Enlarging everything solely to match generic spacing advice |
| Typography | Semantic text roles and actual font tokens | Matching font size while changing role or hierarchy |
| Controls | Shared primitives, action hierarchy, state behavior | A visually similar button with different keyboard or pending behavior |
| Color | Semantic surface/status/action tokens | Hard-coding a sampled color that fails another theme |
| Content | Labels, date/number formatters, status wording | Introducing a second vocabulary for the same object |
| Responsiveness | Real container behavior and source order | Fitting one screenshot while breaking a narrow pane |

For each consequential choice, classify it as documented, repeated current practice, isolated precedent, or new extension. These are evidence categories, not confidence scores. If references disagree, do not average their values; identify which applies to the feature.

For later evaluation, implement the same fictional feature in two distinct test projects, such as a compact operations tool and a spacious editorial workspace. Check whether each uses its own primitives, hierarchy, density, and state conventions. A manual comparison is not a measured user-preference test.
