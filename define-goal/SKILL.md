# Define a goal

Use for an explicit goal-definition or goal-tool request, not ordinary implementation.

Ground one objective in the user's intended outcome, scope, and observable completion evidence. Use a meaningful metric where available; otherwise use an honest pass/fail condition. Resolve routine omissions from context and ask only when an unknown would change the objective.

For a drafting request, return the goal without creating it. For an explicit creation request, inspect active goal state and follow the current goal-tool contract. Reuse a matching active goal; do not replace unfinished work or mark it complete to make room. Set a token budget only when explicitly requested.

Prefer an objective such as 'Fix the checkout regression and verify the affected checkout tests and local purchase flow' over an activity such as 'make progress'. Do not add a separate ledger, mandatory document stack, or metric-confirmation step when the outcome is already clear.
