# Motion implementation plan

Use this optional structure when the requested deliverable is a plan. Include only the detail an executor needs; related findings can share a plan.

- Outcome and affected interaction.
- Current behavior, relevant source locations, and supporting evidence.
- Proposed change using existing project tokens and conventions. Give concrete starting values where useful and explain what needs tuning.
- Essential product or data boundaries.
- Verification: trigger the interaction, check interruption and reduced-motion behavior, and run relevant project checks.
- Completion: observable behavior that establishes the improvement.

When the code has changed since the plan, inspect it and adapt routine implementation details. Ask only if drift changes the intended outcome or an important boundary. Do not require fixed steps, a separate plans index, a new dependency prohibition, or copying entire source blocks unless the task needs them.
