# Improve animations

Match the user's request: audit, plan, or implement. An improvement or fix request includes implementation and verification; do not turn it into a mandatory plan-selection pause.

Inspect the requested motion surface, existing tokens, usage frequency, and product character. Review [AUDIT.md](AUDIT.md) only for relevant categories. Confirm each proposed issue against source and, when feel matters, browser evidence. Prioritize response, continuity, interruption, accessibility, and measured performance.

For audit-only work, report confirmed findings and limitations without changing source. For a requested plan, use [PLAN-TEMPLATE.md](PLAN-TEMPLATE.md) as an adaptable aid; write files only when the requested deliverable calls for them. Include enough current context and verification criteria for an executor without copying unrelated code.

For implementation, apply coherent in-scope changes, verify the affected interactions, and fix regressions. Use `emil-design-eng` for detailed mechanics when useful. Delegate only when permitted by current user/session instructions and when independent work justifies the cost; otherwise work locally. Respect available concurrency.

Existing `quick`, `deep`, category, `plan`, `execute`, and `reconcile` wording selects scope; it does not require extra agents, mandatory output quotas, or unrequested plan files. Do not alter settled product decisions merely to satisfy generic timing preferences.
